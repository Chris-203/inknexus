# InkNexus

Every series. One place. A mobile-first webtoon and manhwa tracker and reader.
TypeScript and React, bundled by Vite. Deployed on Vercel at https://inknexus-psi.vercel.app.

## Workflow
- `main` is protected. Every change goes through a branch and a pull request. Do not push to `main`.
- Each PR gets a Vercel preview. Check the change there, at phone width, before merging.
- Keep PRs small and single-purpose. Refactors that change no behavior get their own PR.

## Commits and PRs
- Branch names start with `chris/`, for example `chris/fix-add-link-overflow`.
- No `Co-Authored-By` trailer or other attribution lines in commit messages.
- PR bodies are kept simple: markdown headers `## What changed`, `## Why`, `## How to test`, `## How it was tested`, each followed by plain sentences.
- No mention of Claude Code, sessions or session links anywhere on GitHub: commits, PR bodies, and PR or issue comments and replies. That includes the "Generated by Claude Code" footer; if a tool adds it, edit it out.
- Include screenshots or other media of the change in the PR body when there is anything visible to show.

## Check before committing
Re-read the full diff against this file, then run all four. The GitHub "Check" action runs them on every PR too, format check included; `npm run format` fixes formatting. Fix what your change broke. Report any check that could not run and any failure that was already there, and never say a check passed unless it ran and passed.

```
npm run format:check
npm run typecheck
npm test
npm run build
```

Run the app locally with `vercel dev`, which also serves `/api/mangadex`. `npm run dev` serves the page without the relay, so MangaDex fails there.

## Layout
- `index.html`: page shell and meta tags; loads `src/main.tsx`
- `src/App.tsx`: navigation (`navigate()`, `goBack()`; views live in browser history so the phone back gesture works), the bottom nav, the toast, backup import. `src/context.ts`: the `View` type and `useApp()`
- `src/views/`: one file per screen, each given its series by `App`: `Library`, `Search`, `Series` (with its source panels and the Add-a-source and Change-name sheets), `Reader`, `Frame` (the in-app site view)
- `src/components/`: `Sheet` (bottom sheet dialog), `LinkFields` (site presets with name and link fields), `ResultRow` (a cover and title row), `ImportSheet` (choose versions when a backup has series already in the library), `ResetZoom`
- `src/lib/store.ts`: the library, saved on every change and read with `useStore()`; `setLast()`, `updateSeries()`, `sourcesOf()`, `setHidden()`
- `src/lib/`: `api.ts` (`api()`, `RELAY`, `why()`), `links.ts` (`parseChUrl()`, `linkFrom()`, `isWebUrl()`, `linkName()`, `chapterLink()`, `stepChapter()`, `PRESETS`), `format.ts` (`fmt()`, `plural()`, `norm()`), `storage.ts` (the `longstrip` key; `toState()` checks saved and imported data; `readJson()` and `writeJson()` for every other key), `changes.ts` (`createChanges()`: the change notifier every store uses), `useLoad.ts` (load something once per key, with busy and error states), `chapters.ts` (`useChapters()`: session chapter cache, one load at a time), `updates.ts` (`useUpdates()`: library "new" badges), `siteSettings.ts` (site zoom and open-in-browser, kept on the device, not in backups), `pasteLink.ts` (update a chapter from a copied link), `importBackup.ts` (match a backup against the library and merge it), `names.ts`, `zoom.ts` (reader pinch and double-tap), `types.ts`
- `src/sources/`: `mangadex.ts` (`toChapterList()` is the chapter filter) and `anilist.ts`
- `*.test.ts`: Vitest tests next to the code they test
- `src/styles.css`: all styles
- `api/mangadex.js`: Vercel Function that relays MangaDex API GETs (CORS workaround) at `/api/mangadex`, limited to `https://api.mangadex.org` and same-site requests
- `assets/`: cover art (`cover.svg` is the source, `cover.png` is rendered from it)
- `public/`: icons, copied as-is into the build
- `vercel.json`: builds with Vite into `dist/`

Library data uses the field names in `src/lib/types.ts`. They match what is already saved in people's browsers, so do not rename them without a migration.

## Code
Follow these on every change, and check your diff against them before committing (see "Check before committing").
- **One code style.** Prettier formats all TypeScript and JavaScript, so never hand-format around it. Module-level functions are `function` declarations; arrow functions are only for callbacks and for handlers inside components. Doc comments use `/** */`; every other comment uses `//`.
- **One file structure.** Screens go in `src/views/` and reusable components in `src/components/`, one component per PascalCase file (a screen may keep its own sheets and panels in its file). Everything else goes in camelCase files in `src/lib/` (app logic and stores) or `src/sources/` (MangaDex and AniList).
- **One CSS style.** All styles live in `src/styles.css`, one rule per line, using the existing classes and the color tokens in `:root`. Add a class rather than an inline `style`; inline styles are only for values computed at runtime.
- **No duplicate code.** Before writing new code, read the relevant code and search for an existing helper, component, store or pattern, and extend it rather than writing a parallel version: `why()`, `linkFrom()`, `linkName()`, `chapterLink()`, `stepChapter()`, `fmt()`, `plural()`, `sourcesOf()`, `setLast()`, `readJson()` / `writeJson()`, `createChanges()`, `useLoad()`, `useChapters()`, `ResultRow`, `Sheet`. When the same logic would appear a second time, move it into one place and use it from both. If existing code cannot support the change, say why in your reply; ask first only before replacing a whole module or changing saved data.
- **Clear, then short.** Write code a reader can follow on the first read. Then tighten it: cut duplication, dead branches, needless variables and wrappers, and use an existing helper or built-in where it says the same thing in fewer lines. Stop when the shorter version would need a comment to explain it, packs several steps into one expression, or relies on a trick. Do not shorten working code outside the change. React is the only UI library, and shared state is a small store in `src/lib/` built on `createChanges()`; add no library, layer or option the problem does not need.
- **Keep changes focused.** Make the smallest change that fully does the job. No unrelated refactors, renames, file moves or behavior changes; if a wider change is needed, say why in your reply.
- **Preserve behavior.** Unless the request changes it, keep existing behavior, exported functions, data formats and conventions. Before changing shared code, check its callers and keep their cases working.
- **Name things for what they are.** Follow the names already in use (`x` for a series, `l` for a link, `n` for a chapter number), and keep the field names in `types.ts` as they are.
- **No filler.** Comments explain why, not what. UI text, commit messages and PR bodies say what changed in plain sentences, without padding.
- **Tests.** Add or update a `*.test.ts` next to the code for each new or changed helper and each fixed bug in `src/lib/` or `src/sources/`, including edge cases. For a bug fix, add a test that fails without the fix when practical. Check UI changes on the Vercel preview at 390px wide. Never weaken or delete a test to make it pass.
- **Report back.** After code changes, say in your reply (not in the PR body, which follows "Commits and PRs"): what changed, which existing code you reused or extended, which checks ran and their results, and what is still limited or untested.

## Rules
- **Storage key stays `longstrip`.** It predates the rename. Changing it makes every saved library look empty. If it ever must change, migrate the old key.
- **The relay stays narrow.** `api/mangadex.js` forwards GET only, only to `https://api.mangadex.org` (checked with `new URL()`, not string prefixes), and only for same-site requests. Never turn it into an open proxy, add CORS headers, or relay image hosts or other sites. No secrets or hardcoded site addresses in the repo.
- **Sources policy.** The built-in reader is only for sources with an API that allows it (MangaDex, under its API rules). Everything else is link-only: the user pastes a chapter link and the app reads the chapter number. For unlicensed scanlation sites the app may know a site's name and main address (for example to prefill a link), and may open the site's own page, but it must never fetch, scrape, mirror, proxy or hotlink their pages or images, and never read their chapters inside the app's reader.
- **Original artwork only.** Do not add real covers, characters or logos. Cover art in `assets/` is original.
- **Mobile first.** Check at about 390px wide. Keep visible focus states, keep touch targets at least 44px, keep inputs at 16px text (iOS zooms in on smaller ones), respect `prefers-reduced-motion`. Do not block browser zoom; only the reader's pages have their own pinch zoom.
- **Failure messages say what failed and what to do.** Do not swallow errors silently.
